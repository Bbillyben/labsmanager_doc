# Screenshot specification

Source path for output files: `docs/`. This human registry specifies capture targets and states. For each batch, Codex writes the machine-readable request to `screenshot-request.json`; external Playwright writes PNGs and `screenshot-result.json`. A PNG can be considered for documentation only when the matching batch result reports `success` and the file exists. Visually check that it shows the expected settled UI state before integration.

Every capture added to, replaced in, or removed from the published documentation must be updated here. For each integrated capture, retain its request ID, profile, scenario, parameters, capture type, output, target page and status. `SCREENSHOTS.md` is the source of truth for global visual refresh batches: include only currently validated and integrated captures, never requested, waiting, conditional, deferred, rejected or obsolete ones. `Output file` is relative to `docs/`; the request `output` is the same path without the `assets/screenshots/` prefix.

## Reproducibility contract

- Browser: Chromium
- Viewport: **1440 × 900**
- `deviceScaleFactor`: **1**
- Theme: **light**
- Language: **English**
- Dataset: **Synthetic Demo Dataset**, seed **42**
- Production data: **forbidden**
- Manual cropping after capture: **avoid**; capture the required viewport or region in Playwright.
- Captures must be reproducible automatically. Keep routes, selectors and profile assumptions verifiable against the demo instance.
- Keep the sidebar visible in general captures unless a row justifies another state.

Capture types: **full viewport** (entire application viewport), **component / region** (a stable UI area), **stateful interaction** (opened menu, search or filter state). The `P0-finalization` result reports six successes. All six PNGs have matching `success` results and pass visual review; all six are integrated.
